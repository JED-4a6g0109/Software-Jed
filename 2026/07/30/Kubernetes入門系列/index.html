Kubernetes 入門：從部署演進看懂容器編排解決了什麼

發表於2026-07-30|更新於2026-08-27|Cloud NativeKubernetes
|瀏覽量:

前言

在前幾年容器化開發非常火紅，解決了像是系統移植問題、環境隔離、更輕鬆雲端佈署，其實一直有Docker與Docker Compose經驗，但實在沒有實際Kubernetes工作經驗，因為位置在後端工程師，基本上負責Kubernetes都是SRE工程師，而最近剛好工作有接觸而工作內容又跟Kubernetes有相關，再慢慢接觸與認識後真心覺得Kubernetes非常重要，他不只是單單用來編排容器而已，更重要的是他的一些設計概念與知識對於後端工程師是有幫助的，我認為我要好好寫個完整Kubernetes入門系列，以及他的設計和實務上解決什麼問題。

由於Kubernetes內容非常多，我打算分篇一一介紹Kubernetes，因為他真的太多內容了，到後面他還能延伸各個雲原生工具。

部署演進史

在認識K8S之前先講以前伺服器是如何部署的。

傳統部署

直接裝了兩個 Tomcat又或者Apache，每個 各跑一個 Java 應用(war 包)。問題在於兩個應用共用同一套作業系統環境，同一份系統函式庫、同一組系統資源、甚至同一個網路 port 範圍。任何一個應用出狀況(記憶體洩漏、CPU 打滿、依賴版本衝突)，都可能拖累另一個，完全沒有隔離性。

虛擬化部署

同一台實體伺服器，透過虛擬化技術切成多台虛擬機，每台虛擬機各自有獨立的 Linux 作業系統，裡面再各自跑一個 Tomcat + Java 應用。這樣一來應用之間互相隔離了，各自有獨立的作業系統、獨立的資源配額，一個掛掉不會直接波及另一個。

但代價是每台虛擬機都要背一整套完整的作業系統，啟動慢、佔用資源多，伺服器的整體資源利用率不高導致浪費。

容器化部署

為了解決以上兩者部署缺點，在Linux上使用 LXC(Linux Containers技術，他是一種作業系統層的虛擬化技術，在單一主機上執行多個獨立的 Linux 系統環境。容器化帶來了

  • 共用作業系統核心:整台伺服器只跑一套 Linux 作業系統，不像虛擬化部署要一整套獨立的 OS。

  • 各自獨立的容器環境:透過容器引擎(例如 Docker)，把每個 Tomcat + Java 應用包成一個獨立的容器，容器之間有各自獨立的檔案系統、網路空間、資源限制，互相隔離不會像傳統部署那樣互相干擾。

  • 輕量、啟動快:因為容器不用背整套作業系統，只打包應用本身需要的執行環境和依賴，所以體積小很多，啟動速度是秒級的(如果有玩過虛擬機通常要分鐘級很慢)。

  • 資源利用率高:一台伺服器可以塞下遠比虛擬機更多的容器,硬體資源用得更有效率。

容器化一些問題

由於容器有生命週期且可能會很短，像是建立、重啟、刪除，對於傳統上配置如硬碟、網路配置都是固定的，但容器每次刪除或重啟都有可能會遺失資料或配置，對於容器上的服務像是後端服務，這些配置都不會想要變動的一變更都是災難，因此才有了Docker的出現，但Docker只能針對單一主機做管理，如果要多台主機以上就得需要Kubernetes來管理控制了，Kubernetes不僅僅解決單純這些配置問題，後面將會介紹Kubernetes威力有點多強。

Kubernetes

Kubernetes，中文圈又常簡稱 K8s，取首尾字母加中間 8 個字母而來，是一個開源的容器編排系統，最初由 Google 開發，現由 CNCF維護。負責自動管理大量的容器，要跑在哪台機器上、掛了要不要重啟、流量怎麼分配，這些事都交給它處理。

Google有個系統叫伯格(Borg)，Kubernetes是基於這系統的優點，以及改善缺點而誕生的。

如果有玩過Docker Compose其實就是一樣概念，只是Kubernetes他是管理多台設備與雲平台上容器，當然Docker Compose也能做到，但需要依靠docker swarm，但現況docker swarm基本已死去，目前主流還是Kubernetes為主。為了方便寫Blog 文章我將Kubernetes都稱為K8S。

上面介紹可能非常無趣且抽象，我這邊就講述一下關於docker、 docker compose、Kubernetes Logo設計含意

結論

到這邊我們從傳統部署 → 虛擬化部署 → 容器化部署一路講到 Kubernetes 為什麼會出現，核心觀念是：

  • 容器化解決了資源利用率與環境隔離的問題，但單機管理（Docker）在多機規模下會失控
  • Kubernetes 的角色，就是把「一堆容器要跑在哪、掛了要不要重啟、流量怎麼分配」這些瑣事自動化，讓我們能用宣告式的方式管理整個叢集

這篇算是講述背景知識，讓後面看到 K8s 的架構與元件時，能理解「為什麼要這樣設計」，之後會一一介紹。
