什麼是向量？讓電腦學會「看懂」特徵

我在逛大賣場或者3C都會有個習慣就是開蝦皮，然後拍照以圖搜圖來比價網購比較划算還是在實體店面比較划算，然而在用這以圖搜圖技術讓我充滿好奇心想了解它背後的原理，身為後端工程師肯定要去了解裡面到底用了啥，所以此篇文章將講述從這動機一路學習，ANN 演算法，HNSW、IVF 與 PQ 向量檢索技術。

以下為三種狗，雖然風格不一致但你總是能辨別，這是因為我們大腦從出生到現在已經把狗的特徵記住在腦子裡，比如長長的耳朵、大大的狗鼻，長長的舌頭

因此電腦也能按照大腦這種方式，將特徵保存起來，例如我們有個向量XY座標軸，X軸為耳朵長度，Y軸為舌頭長度，將狗狗放入座標軸內位置會偏向X與Y較高的數值點位上

然而我們再把貓咪加進來，那就與狗狗座標軸分布相近，這時就會再加上一個維度w軸，而w軸上為鬍鬚的長度，而貓咪的鬍鬚是長的，狗狗的話幾乎沒鬍鬚或很短，這時w軸上就能區分出貓與狗兩群。

因此我們可以根據特徵數來增加維度，例如毛髮、顏色、斑點、體型等，當貓與狗的照片當考慮到照片的光線、位置、角度等因素時，實際上還有非常多維度(像圖上標的 128 維)，周圍散佈的彩色圓點就是不同的資料向量，落在不同位置代表牠們在這些特徵上的數值組合不同。

每一條軸就是一個特徵維度(尾巴、臉型、鬍鬚、體型、毛色、叫聲……)，在每一條軸上都會得到一個介於 0~1 之間的浮點數。把這些數字依序排列起來，例如 (0.51, 0.33, 0.83, 0.25, 0.53, 0.42, …)，程式會得到一組數據存放各維度浮點數，因此可以推出一張狗貓照片的向量。

如果總共有 128 個這樣的特徵軸，這張照片就會被表示成一個 128 維向量。兩張照片如果向量裡的數字都很接近，代表這兩張照片在模型眼中「長得很像」;數字差距越大，代表差異越明顯。

高維度搜尋與 HNSW 小世界網路

當圖片轉換成向量，將向量與向量資料庫數據一個一個找計算向量的相近距離，但這會衍生個問題，資料量巨大達到百萬甚至上千萬時這種暴力搜索就顯得非常慢。

那B+樹不能解決嗎?答案是不行，B+ 樹是為「一維、可排序」的資料設計的，B+ 樹的效率建立在一個前提上，資料可以被排出一個明確的順序(例如數字大小、字母順序)，這樣才能用「二分」的方式不斷縮小搜尋範圍,達到 O(log n) 的查詢效能。它非常適合處理像「主鍵、日期、金額」這種單一維度、有明確大小關係的欄位,做等值查詢或範圍查詢(BETWEEN、ORDER BY)特別快。

但前列所提到向量是一組多維浮點數，例如 (0.51, 0.33, 0.83, 0.25, …)。多維空間裡沒有一個「唯一正確」的排序方式，你要按第一維排序?第二維?還是整體距離?一旦維度超過 1，B+ 樹「全序關係」就不存在了。

那向量又該怎搜索呢?這邊來提一下六度人脈理論概念，世界上任何兩個互不相識的陌生人，只需要透過最多六個中間人就能建立起聯繫，每個彩色點是一個向量，只有「距離相近」的點才會被連上一條邊。

因為不是每兩個點都互相連接，所以整個網路看起來稀疏又不規則，但因為每個點都跟自己附近的點相連，你只要沿著邊跳個幾步，就能從網路裡任何一點走到另一點，這就是六度分隔理論的精神，也是 HNSW 名字裡「Navigable Small World(可導航小世界)」的由來。

但因為向量點非常多，所以切入點很重要，因此「分層」概念就出現了類似金字塔最上層節點最少，往下每一層節點越來越多、邊越來越密，最底層才是包含「所有」向量點的完整圖。

參考下圖中的虛線代表「同一個節點在上下相鄰層都存在」(這是 HNSW 建圖時用機率決定的，越上層的節點越稀少)。搜尋時的路徑就是:

從最上層入口出發 → 沿虛線下探到中層對應的節點 → 再下探到最底層 → 最後在最底層的完整圖中,沿著邊一步步走向真正離查詢向量最近的節點(圖中紅圈標示的結果)。

在中層加了一個小示意(綠色虛線圈的「+ 新節點」):當有新資料要加入時，系統會先用同樣的方式，從入口一路往下找到該插入的層，找到後就在那一層裡把新節點跟附近幾個最近的節點建立邊連結，之後別人搜尋時就能透過這些新邊「路過」這個新節點。這也是為什麼 HNSW 能一邊持續新增資料，一邊維持搜尋效率的原因。

關於上層是如何選出的?肯定有這一問，答案是上層是隨機挑選，因此一層一層往上直到全局唯一入口點。

當然HNSW有個問題，貪婪搜尋卡在局部最優(Local Optimum)，如果圖裡剛好有個「更近的點」被擋在一個目前看起來沒那麼近的節點後面、而且兩者之間沒有邊直接連接，貪婪演算法可能會在中途就停下來(因為周圍鄰居都沒有比目前節點更近)，收斂在一個「局部最優解」，而不是真正的全局最近點。

IVF(Inverted File)

HNSW雖快但須要把整張向量圖存放在記憶體中，數據量一大記憶體就用更多，為了節省記憶體空間出現了IVF。IVF概念是先對向量進行分類。

就像你去超市要買葵花油你一定會先看天花板上的看板標示文字油這分類。會先將相似向量存放資料桶裡，每個桶都有個聚類中心Centroid，這聚類中心代表桶的其他向量，是透過數學計算出來的一個虛擬向量，代表了該群組內所有向量的「平均位置」。因此在記憶體中只需要存聚類中心和桶文件，無須文整個向量省去一些空間。這種先做一個分類再做查找稱為IVF。

例子:
「看天花板看板（油類）」，就是 IVF 搜尋時「先找聚類中心」的過程；而「走到油品貨架」，就是「進入對應的桶文件（群組）裡找葵花油」。

  • 天花板的看板 = 聚類中心 (Centroid)：它代表了這一個區域的「核心主題」（平均位置）。

  • 特定的貨架區 = 桶文件 (Inverted List / Bucket)：同一個種類的向量通通集中放在這裡。

但還有個問題，向量不一定精準落在對應的桶，這就是邊界問題(Boundary Problem)，如果查詢向量剛好落在兩個聚類中心的「交界處附近」，真正最近的那筆資料很可能被分在隔壁的桶裡，但 IVF 通常只搜尋距離最近的 1~N 個桶(這個 N 叫 nprobe)，如果隔壁桶沒被選中，那筆資料就直接被漏掉，連比較的機會都沒有。

  • 你決定看幾個看板 = nprobe 参数：如果你只看最像的 1 個看板（nprobe=1），速度最快，但如果葵花油被店員放錯在「健康食品區」，你可能就漏掉了(失真)。如果你看了 3 個看板（nprobe=3，如：調味品區、健康食品區、進口食品區），你找到葵花油的機率就大幅提升。

PQ 乘積量化與極致壓縮

我們現在有個 128 維的向量：
[0.1, 0.2, 0.3 ..., 0.3]

而在電腦每個維度向量為 Float，而單精度浮點數 (Float) 佔用 32 bit（4 bytes），如果有 1 千萬向量資料就為：

  • 128(維) * 4(bytes) * 10,000,000(數據向量) = 5,120,000,000 Bytes

換算成記憶體為：

  • 5,120,000,000 Bytes / 1024 / 1024 / 1024 約為 4.768 GB

也就是說向量資料量越大，所占內存光是 1 千萬就要接近 5GB 記憶體，且查詢一與桶內向量逐個計算又浪費了時間，那該怎節省呢？

為了更清晰理解，將 128 維改為假如有 3 組 4 維向量，這邊為了解釋將 float 改為 int：

將四維向量切成兩段的二維向量：

前面切好的兩段子向量，對每一段做一次分群，找出每一段空間裡的幾個「代表點(中心點)」，在每個向量就不再存原始數字，而是只存它離哪個聚類中心點最近的編號來表示。

  • 第一段 [x1, x2]
    A(2,3)、B(8,7)、C(5,3)。
    A 跟 C 離得近自成一群，中心點記為 編號 0。
    B 自己離得遠，自成一群，中心點記為 編號 1。

  • 第二段 [x3, x4]
    A(9,9)、B(5,1)、C(7,3)。
    這次換 B 跟 C 離得近成一群，編號 0。
    A 自己一群，編號 1。

這樣就能得出儲存空間壓縮倍數：

壓縮前

  • 每組向量大小 = 4 個 float × 4 bytes = 16 bytes
  • 3 組向量總大小 = 16 bytes × 3 = 48 bytes
  • 總共需要 48 bytes × 8 = 384 bits

壓縮後

向量 第一段編號(1 bit) 第二段編號(1 bit) 這組向量共需要
A [2,3,9,9] 0 1 2 bits
B [8,7,5,1] 1 0 2 bits
C [5,3,7,3] 0 0 2 bits

2bits + 2bits + 2bits = 6bits

所以可以得出壓縮完後：

  • 384bits / 6 bits = 節省64倍

但實務上電腦通常還是以 1 byte 為最小儲存單位(不太會真的去存 2 個 bit)，所以現實中會存成 2 個 byte(每段各占 1 byte)：

  • 2bytes + 2bytes + 2bytes = 6bytes
  • 48 bytes / 6bytes = 實際大約壓縮 8 倍記憶體

此外除了節省記憶體還能高效查詢，我們現在加入一個查詢向量，示範 PQ 是怎麼「不用比對原始向量」就能快速估算平方距離的。

設查詢向量 Q = [3, 4, 8, 9]

  • Q1 = [3, 4] (對應第一段)
  • Q2 = [8, 9] (對應第二段)

PQ 查詢向量只需要跟每段各自的 2 個中心點算距離，完全不管資料庫裡有幾筆資料：

第一段查詢表

  • Q1 到 中心0(3.5, 3): (3.5-3)²+(3-4)² = 0.25+1 = 1.25
  • Q1 到 中心1(8, 7): (8-3)²+(7-4)² = 25+9 = 34

透過平方歐氏距離來計算

第二段查詢表

  • Q2 到 中心0(6, 2): (6-8)²+(2-9)² = 4+49 = 53
  • Q2 到 中心1(9, 9): (9-8)²+(9-9)² = 1+0 = 1

兩張小表就是查詢表(Lookup Table)，總共只算了 4 次距離，跟資料庫有多少筆向量完全無關，不需逐一向量算距離，A、B、C 早就被壓縮成編號了，現在直接拿編號去查表：

向量 編號 查表結果 加總(近似距離²)
A [0,1] 段1查0→1.25,段2查1→1 1.25 + 1 = 2.25
B [1,0] 段1查1→34,段2查0→53 34 + 53 = 87
C [0,0] 段1查0→1.25,段2查0→53 1.25 + 53 = 54.25

跟我們故意設計 Q 接近 A 的預期一致。IVF加上PQ稱為IVFPQ。

近似最近鄰搜索(ANN, Approximate Nearest Neighbor)

IVF:透過分群將資料空間分成多個聚類，查詢時只搜尋最相關的幾個聚類，速度快且省記憶體。但有邊界問題剛好被漏掉。

HNSW :建立多層的小世界圖結構，透過層層導航來精準定位向量，準確率極高但記憶體開銷大。但有貪婪搜尋卡在局部最優。

PQ: 高效向量檢索與壓縮方法，透過IVF聚類編號來替換值，速度快且省記憶體。但因為替換關係，所以會缺失一定的精度。

三者特性都是犧牲極少數的準確度，來換取速度與效能的大幅提升，稱為近似最近鄰搜索(ANN, Approximate Nearest Neighbor)

向量數據庫

能將各種不管是文字、聲音、文件、數字萬物皆向量化，將向量存取在資料庫，並把圖片轉成向量，可以查詢並返回，這就是量化數據庫，當然內部一定有更多細節，但有了前面各項技術介紹，現在對於量化資料庫就能了解不少了。

這就是為什麼人臉辨識、圖片搜尋、推薦系統背後都是在做「向量之間的距離比較」每一筆資料都變成一組浮點數，再用數學方式衡量相似度。

結論

前幾年出現的RAG還一些以圖搜圖原理上都是基於這些向量化技術，其實認真去了解這塊技術很有趣，在生活中的應用非常多，我想在AI的發展下，後端工程師除了關聯與非關聯資料庫外，又要多學習向量資料庫了，不過看完各種文章真的覺得數學真的很重要，在國中學向量完全不知道要幹嘛，如今28歲終於搞懂向量其中一門應用了，真是有趣。
