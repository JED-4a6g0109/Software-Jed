AI Agent 入門：從旅行規劃理解 Planning、Memory 與 Tools

發表於2026-08-17|更新於2026-08-27|AI
|瀏覽量:

AI Agent是什麼?

其實你已經知道Agent是什麼了，只是太多深疏的專有名詞你不能理解，這邊舉個例子，假如快放長假了，你女朋友突然想要去日本，那你會怎做呢? 身為一個男朋友通常會分幾步驟:

  • 聽你女友想去日本哪邊、想吃什麼、想住什麼類型飯店
  • 開始上網開起工具(Google、IG)，開始尋找機票、飯店、網美景點、好吃的好料、交通、伴手禮店
  • 然後你會將這些記錄(女友要求、查詢日本相關資訊等)陸陸續續紀錄在Line上阿，或者兄弟DC群阿等等
  • 最後將結果輸出上報給女友大人等待好玩的日本之旅

其實你就等於Agent，Agent做的事情概念與你相同

步驟 對應 Agent 模組 對照重點
聽女友想去哪、想吃什麼、想住什麼飯店 推理與規劃(大腦) 理解需求、拆解成「地點、美食、住宿」等子任務
開 Google、IG 找機票、飯店、景點、美食、交通、伴手禮 感知交互(工具) 調用不同工具(Google、IG)去外部獲取資訊
陸陸續續把女友要求、查到的資訊記錄在 LINE 或兄弟 DC 群 狀態管理(記憶) 重點就在「陸陸續續」——不是查完一次性記錄,而是邊查邊更新、持續累積,同時保留女友最初的要求當作對照標準
彙整結果上報給女友大人 匯總輸出(結果) 把零散記錄整合成一份完整、有條理的行程結果

Agent整體架構

Agent = 大模型 + 規劃 + 記憶 + 工具，Agent用一句話解釋就是「就是代理你這個人或流程」。而更完整版本的 Agent 架構是由Lilian Weng(OpenAI 研究員)在 2023 年 6 月寫的一篇部落格文章《LLM Powered Autonomous Agents》，一個Agent會分成

  • Planning(規劃) : 包含 Subgoal and decomposition(任務拆解)、Reflection and refinement(反思與修正)
  • Memory(記憶) : 分 Short-term memory(等同 in-context learning,模型當下上下文記住的東西)、Long-term memory(外部存儲、可長期檢索)
  • Tool use(工具使用): Agent 學會調用外部 API、工具來彌補模型本身的限制(比如算數、查即時資訊)

圖片Overview of a LLM-powered autonomous agent system. 來源

這種「感知→思考→行動」的循環，讓 AI Agent 就像人類一樣，不只是被動回應任務，
還能主動利用資源解決問題，實現更高層次的智能化。

  • 感知:聽懂女友說「想去日本、預算多少、想住溫泉飯店」
  • 思考:拆解成訂機票、訂飯店、排景點幾個子任務,並邊查邊調整(比如發現預算不夠要改方案)
  • 行動:實際打開 Google、IG 去查、去訂

單一 Agent 的問題

由於這三項是出於個人去執行，也就是一手包辦感知、思考、行動，但很有可能衍伸一些問題:

1. 能力/專業度/經驗有極限

如果你是第一次規劃與女友出國，可能會先做幾件事:

  • 問有去日本遊玩的朋友
  • 問住日本的親友
  • 問在航空公司上班的朋友
  • 問 IG 女性朋友網美景點跟美食

因為一人知識或經驗有限，沒有經驗與知識的情況下，很難規劃出一個精緻之旅。

對應 Agent:單一 Agent 知識能力有限，需要不同專精領域的 Agent 協作(機票專家、飯店專家、行程規劃專家)，品質會比一個什麼都懂一點的 Agent 更好

2. 任務太複雜易出錯

一個人同時處理女友需求 + 查資料 + 記錄 + 整合，腦袋會打結，忘東忘西的機率變高。

對應 Agent:步驟一多容易前後矛盾、遺漏最初的限制條件(如溫泉飯店需求)

3. 缺少互相檢查機制

規劃一個段落，但沒預想到可能下雨、店家是否有開等因素，這些都需要有人去檢查，
自己一個人做很容易有盲點。

對應 Agent:對應「競爭式協同」，多個 Agent 互相檢查、裁決，避免單一視角的盲點

Multi-Agent(多智能體)

因此才會有後續 Multi-Agent(多智能體)協同工作架構。

上下級協同

  • 中控 Agent:你自己。負責彙整女友需求(想去哪、預算、想住溫泉飯店)，
    拆成「機票」「住宿」「行程」三大任務，分派下去
  • Sub-L1 Agent:
    • 訂機票的阿昇(負責比價、查航班)
    • 訂飯店的阿浩(負責篩選溫泉飯店)
    • 排行程的阿倫(負責景點跟交通)
  • Sub-L2 Agent(阿倫底下再細分):
    • 查網美景點的小郁(阿倫的同學IG 特別厲害)
    • 查美食的阿賢(阿倫的酒肉朋友專門吃遍日本)

你(中控)最後把大家回報的資訊彙整成一份完整行程。

師生式協同

  • 專家 Agent:你的學長，去過日本十幾次，深諳規劃訣竅
  • 傳遞內容:
    • 集劃思路:先訂機票再訂飯店，行程要留緩衝時間
    • 信息收集:哪些網站查機票最準、哪個 App 訂飯店有折扣
    • 表達格式:行程表要怎麼排版女友才看得懂(不要密密麻麻)
    • 評價標準:怎樣算精緻的行程(不能太趕、要留自由活動時間)
  • 新手 Agent:第一次規劃出國行程的你

學長不是直接幫你排好行程，而是教你「怎麼想」，讓你自己有能力規劃。

競爭式協同

  • 競爭式協同:你和兩個兄弟(阿昇、阿浩)各自規劃一套完整的三天行程方案
    • 決策1:阿昇的方案(重美食、輕購物)
    • 決策2:阿浩的方案(重打卡景點)
    • 決策3:你的方案(重悠閒步調)
  • 裁決:三人一起開會比較，或直接讓女友當裁判，選出最喜歡的方案
  • 最終決策:整合出最終行程，交付執行

小結

從 Agent 是什麼、多 Agent 如何協作，到 Planning / Memory / Tools 這些核心模組，本質上都可以對照到人類處理任務的方式。很多概念不是難懂，而是技術名詞一開始很陌生；後續文章會再分別拆解 Agent 的核心能力。

Reference
