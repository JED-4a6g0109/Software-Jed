目前我們已經對Agent有一定的深度了解，那該如何實現呢? 接下來將開始介紹低階的Agent 編排框架 LangGraph

為什麼需要 LangGraph?

LLM 本質上是一次生成一段文字的服務，沒有記憶、不能自己執行任何外部動作。要做一個「查詢天氣、記得對話、能被打斷審核」的完整 Agent，這些其實你可以用Python也一堆if-else去創建一個Agent，但是你需要自己維護狀態、寫分支邏輯、處理迴圈跟中斷恢復，甚至每個模型的定義跟串接都要自己處理，很多非常細部的細節，並不是那麼簡單就能處理。

而LangGraph 把這些複雜的概念與實作通通都抽象成標準化的元件，並用「Graph(圖)」這個資料結構標準化與建置Agent。

圖的三個核心

LangGraph 把任何流程都建模成一張圖，有三個部分:

  • State(狀態):一個共享的資料結構，貫穿整個執行過程
  • Node(節點):一個函式，可以接收State資料做事情，並回傳要更新的部分
  • Edge(邊):定義「做完這個 node，接下來去哪」，可以是固定的，也可以是條件式的

就像數學意義，兩個點之間可以連一條邊

  • 點 = Node
  • 邊 = Edge
  • 多出來的一份所有點共用的資料 = State

和數學的圖比，只有一點不同，LangGraph 的邊有方向，A 到 B 和 B 到 A 是兩條不同的邊。如果覺得太抽象，用健康檢查情境為例

  1. 進醫院大門：這是 START，表示流程開始，只是入口，不做任何事
  2. 大門口沿著路走到健檢中心：這是一條 edge，連接 START 與第一個 node
  3. 在櫃台報到：這是第一個 node，有人在這裡幫你建立健檢單
  4. 依照地上的指引路線走向第一站：這又是一條 edge，只負責帶路
  5. 在檢查站，護理師檢查並填寫健檢單：這是 node 在做事，同時更新 State
  6. 依照指引路線前往下一站，重複步驟 5
  7. 最後一站結束後走向出口：這是 END，流程結束

對應下來為

LangGraph 健檢中心 一句話
Node 檢查站 做事的地方，並把結果寫進 State
Edge 地板導引線 有方向的線，只負責連接
State 電子健檢單 共用的一份資料，各站只寫自己那一格
START / END 大門口 / 出口 入口與出口，不是 node，不做事

建立LangGraph

上面我們建構了LangGraph的概念與知識，現在我們建構健康檢查案例，建構State、Node(節點)、Edge(邊)

在建構前，可以先構思或者看圖中進行分析，先定義State需要哪些資料，Node有哪些，Edge該怎建構邊

首先是State，檢查者會有這些檢查單資訊

  • 受檢者姓名 : str
  • 是否報到: bool
  • 血壓: int
  • 視力檢查: float
  • 流程紀錄: list[str]

小結

  • State/Node/Edge 三個元素組成圖
  • Node 是純函式，只 return 要更新的欄位，不要直接修改傳入的 state
  • Reducer 決定欄位是「覆蓋」還是「累加」
  • 善用圖視覺化除錯
