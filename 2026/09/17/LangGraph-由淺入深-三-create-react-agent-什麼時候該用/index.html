上一篇手刻的 ReAct Agent,總共寫了:State、llm_node、route、建圖(4 條 edge)。LangGraph 把這整套「LLM 決策 + 工具迴圈」封裝成一個現成函式:

三行，沒有 State、沒有 node、沒有 edge、沒有 route 函式——create_react_agent 內部自動建好一模一樣(甚至更完整)的圖結構。

完整code

result

那手刻的意義是什麼?

create_react_agent 內部的圖結構是固定死的

「LLM 決策 → 條件判斷 → 工具執行 → 繞回 LLM」

能調整的是 model、tools、system prompt 這些「參數」，圖的形狀本身動不了。但並不是所有情境都可以接受

  • 想在工具執行前插一個「人類審核」node(human-in-the-loop)
  • 想要「先查詢知識庫,再讓 LLM 決策」而不是「LLM 自己決定要不要查」
  • 想要多個 LLM 分工(而不是單一 LLM 決策迴圈)
  • 想要在某個條件下,工具執行完直接結束,不繞回去讓 LLM 再看一次
  • 想要在特定 node 之間插入自訂的資料轉換邏輯

判斷準則

create_react_agent 適合「單一 Agent、標準 ReAct 迴圈」的快速原型，一旦需要客製化圖的結構本身(不只是換工具或換 model)，就要退回手刻。

小結

三行的 prebuilt agent 跟十幾行的手刻版本，功能上幾乎等價，但彈性天差地遠。先評估需求:如果只是標準 ReAct 迴圈，用 prebuilt 節省時間，一旦要客製化流程結構，直接手刻。
