AI Agent Tools：讓模型從只會講變成「真的能做」

發表於2026-09-18|更新於2026-09-29|AIAI AgentLLM
|瀏覽量:

前面兩篇分別講了 Planning（想清楚怎麼做）跟 Memory（記得住什麼），這篇來把 Agent 核心四大模組的第三塊拼上：Tools。

  • Memory
  • Action
  • Planning
  • Tools

圖片Overview of a LLM-powered autonomous agent system. 來源

為什麼 LLM 需要 Tools

回想女友吵著要去日本玩的例子，你負責規劃行程(Planning)，也把女友的需求跟查到的資訊陸續記在 LINE 上(Memory)，但光靠這兩樣，你還是訂不到機票、訂不到飯店，因為這些事情不是用腦子想就能完成的，你得打開 Google、開 App、甚至打電話給航空公司，而這些就是 Tools 在做的事。

大型語言模型本質上是個「文字接龍機器」，它只會根據訓練時記住的東西生成文字，沒辦法真的幫你查今天匯率、訂機票、查資料庫。就像你腦袋再怎麼會規劃行程，沒有 Google Maps、沒有訂票網站，你也只能空想。

關於「LLM只會根據訓練時記住的東西生成文字」，可以透過詢問方式來佐證

Tools 要解決的問題就是讓 Agent 從「憑記憶回答」進化成「可以呼叫外部功能、拿到即時且準確的資訊或執行實際動作」。

Tools 實際上在做什麼

  • 定義工具：告訴模型有哪些工具可以用，每個工具是做什麼的、需要什麼參數（通常用 JSON Schema 描述）
  • 模型決策：模型看到使用者的問題，判斷「這個問題我自己回答得了嗎？還是要呼叫某個工具？」
  • 產生呼叫請求：模型不會真的去執行工具，它只會輸出「我要呼叫 XX 工具，參數是 YY」這樣的結構化內容
  • 外部執行：實際執行工具的是你的程式（呼叫 API、查資料庫、跑計算），不是模型本身
  • 結果回填：把工具執行完的結果丟回給模型，模型根據這個結果繼續推理或組織成最終回答

用女友日本旅遊的例子對照：

步驟 對應 Agent 行為
女友問「機票多少錢」 使用者輸入
你心裡判斷「這個我要查 skyscanner」 模型決策要呼叫哪個工具
打開 App 搜尋 執行 Tool Call
看到票價 3000 元 拿到工具回傳結果
回女友「查到最便宜 3000」 模型整合結果、生成回答

小結

Tools 讓 Agent 變成真正能動手做事的角色。搭配前面的 Planning（決定要不要用工具、用哪個順序）跟 Memory（記住工具查到的結果），此篇章著重於Tools概念，之後會出篇LangGraph來構圖會比較清晰，先暫時知道這些概念就可以了。
